# ELECIO FLOW

**سیستم یکپارچه عملیات کسب‌وکار الکیو** — از اولین تماس با سرنخ تا تأمین قطعات، تولید، انبار، ارسال، نصب، گارانتی و پشتیبانی هر دستگاه، در یک جریان واحد.

Elecio Flow یک *Modular ERP با CRM یکپارچه* است: ماژول‌ها جدا هستند، ولی داده مشترک دارند و رویدادهای هر ماژول به‌صورت خودکار روی بقیه اثر می‌گذارد.

---

## اجرا

پیش‌نیاز: **Node.js 22.13 یا جدیدتر** (از SQLite داخلی Node استفاده می‌شود؛ نیازی به نصب دیتابیس نیست).

```bash
npm install
```

```bash
npm run dev
```

- رابط کاربری: http://localhost:5180
- API: http://localhost:4600 (با متغیر `ELECIO_API_PORT` قابل تغییر)
- در اولین اجرا دیتابیس با پیش‌فرض‌های الکیو و داده نمونه چهار ماهه ساخته می‌شود (`server/data/elecio-flow.db`).
- پیش از اولین اجرا، یک رمز قوی با حداقل ۱۲ کاراکتر در متغیر محیطی `ELECIO_SEED_PASSWORD` تنظیم کنید. این مقدار فقط برای ساخت هش حساب‌های اولیه مصرف می‌شود و در دیتابیس ذخیره نخواهد شد.

ساخت نسخه نهایی (API همان فایل‌های وب را هم سرو می‌کند):

```bash
npm run build
```

```bash
npm start
```

بازسازی کامل داده نمونه:

```bash
npm run seed
```

### حساب‌های اولیه

برای محیط عملیاتی، `ELECIO_JWT_SECRET` و `ELECIO_SEED_PASSWORD` را از طریق secret manager سرور تنظیم کنید. رمزها فقط به‌صورت هش bcrypt ذخیره می‌شوند.

| کاربر | نقش | دسترسی تغییر |
|---|---|---|
| `admin` | مالک | همه بخش‌ها |
| `sara` | فروش | CRM، سفارش، خدمات، کارها |
| `reza` | انبار و تأمین | انبار، خرید، سفارش، دستگاه‌ها |
| `ali` | تولید | تولید، انبار، دستگاه‌ها |
| `neda` | پشتیبانی | خدمات، دستگاه‌ها، CRM |

## محور طراحی: سه موجودیت اصلی

| موجودیت | نقش |
|---|---|
| **مشتری (Contact)** | از سرنخ سرد تا مشتری وفادار؛ همه تماس‌ها، آدرس‌ها، سفارش‌ها، دستگاه‌ها و تیکت‌ها در «پرونده ۳۶۰ درجه» |
| **سفارش (Order)** | ستون فقرات اجرای تعهد؛ مراحل با SLA و «کنترل خروج» (پیش‌پرداخت، تخصیص، ارسال، تسویه) |
| **دستگاه (Unit)** | هر دستگاه با شماره سریال: تاریخ ساخت، دستور تولید، قطعات، فریمور، QC، خریدار، نصب، گارانتی و سابقه تعمیر |

> مشتری شش ماه بعد تماس می‌گیرد؟ با جستجوی شماره سریال یا نام او (`Ctrl+K`)، شناسنامه کامل دستگاه را می‌بینید.

## ماژول‌ها

| حوزه | در Elecio Flow |
|---|---|
| **CRM** | مخاطبین (چند تلفن، چند آدرس با نقشه)، قیف فروش کششی، سرنخ‌های داغ، صف پیگیری (عقب‌افتاده/امروز/این هفته)، ثبت تماس + زمان‌بندی پیگیری در یک قدم، نقشه عملیات، تشخیص شماره تکراری |
| **OMS** | پیش‌فاکتور ← تأیید ← پیش‌پرداخت ← تأمین/تخصیص ← بسته‌بندی ← ارسال ← نصب ← تحویل؛ دو مسیر «فروش از موجودی» و «تولید بر اساس سفارش» |
| **SCM** | تأمین‌کنندگان با کارنامه تحویل به‌موقع و تأخیر میانگین، سفارش خرید با پیگیری حمل، هشدار تأخیر، پیشنهاد خرید هوشمند بر اساس نقطه سفارش |
| **WMS** | چند انبار (قطعات، محصول نهایی، تعمیرات)، موجودی/رزرو/آزاد/در راه، دفتر تراکنش‌ها (کاردکس) قابل ردیابی تا سند مبدأ، میانگین موزون بهای تمام‌شده |
| **MES** | BOM، دستور تولید با مراحل کیتینگ ← مونتاژ ← فریمور ← تست و QC ← بسته‌بندی؛ مصرف خودکار قطعات، صدور شماره سریال، چک‌لیست QC |
| **Service** | تیکت نصب (خودکار با ورود سفارش به مرحله نصب)، پشتیبانی، تعمیر گارانتی/غیرگارانتی، تشخیص خودکار گارانتی از سریال، SLA بر اساس اولویت، یادداشت داخلی، رضایت مشتری |
| **ERP / مالی** | دریافت‌ها، مطالبات، تعهدات خرید، ارزش انبار، حاشیه سود ناخالص، هزینه‌ها (خودکار از خرید و ارسال + دستی) |
| **مرکز فرمان** | جریان یکپارچه (سرنخ ← پیش‌فاکتور ← سفارش ← تولید ← انبار ← نزد مشتری ← تیکت)، «نیاز به اقدام» از همه ماژول‌ها، برنامه امروز، جریان نقدی |

### نقاط اتصال خودکار بین ماژول‌ها

- ثبت پیش‌فاکتور ← مخاطب به مرحله «مذاکره» می‌رود.
- تأیید سفارش ← مخاطب «مشتری» می‌شود.
- ورود سفارش سفارشی به مرحله تولید ← دستور تولید برای کسری ساخته می‌شود.
- خروج دستور تولید از کیتینگ ← قطعات طبق BOM از انبار کسر و شماره‌سریال‌ها صادر می‌شوند.
- تکمیل تولید ← دستگاه‌ها وارد انبار و (اگر برای سفارش بوده) خودکار رزرو می‌شوند.
- ارسال ← سریال‌ها از انبار خارج و گارانتی آغاز می‌شود؛ هزینه حمل به هزینه‌ها اضافه می‌شود.
- ورود سفارش به مرحله نصب ← تیکت نصب ساخته می‌شود؛ حل تیکت ← تاریخ نصب دستگاه‌ها ثبت می‌شود.
- تیکت تعمیر ← وضعیت دستگاه «در تعمیر» و پس از حل، بازگشت به «نصب‌شده».
- رسید کامل خرید ← هزینه خرید ثبت و بهای تمام‌شده کالا به‌روز می‌شود.

## از منابع چه گرفته شد و چه بهتر شد

**منبع ۱ (Tamasa CRM) — الگوی CRM:**
مدل مخاطب با چند تلفن و چند آدرس (استان/شهرستان/مختصات)، مراحل چرخه سرنخ، امتیازدهی خودکار، ثبت تماس + پیگیری، صف پیگیری، قیف کششی، صفحه پتانسیل تبدیل، نقشه خوشه‌ای، داده استان‌ها و تقویم شمسی.

بهبودها:
- **امتیاز سه‌بعدی قابل توضیح**: تناسب با محصول (تعداد ماشین CNC، کنترلر هدف) + تعامل + قصد خرید؛ هر امتیاز دلیل دارد («چرا این سرنخ داغ است؟»).
- **اقدام پیشنهادی** برای هر سرنخ (اولین تماس انجام نشده، سرد شده، ارسال پیش‌فاکتور…).
- **فیلدهای سفارشی** و آستانه‌های امتیاز قابل تنظیم.
- مرحله «واجد شرایط / دمو» و **دلیل از دست رفتن** اجباری.
- **پرونده ۳۶۰ درجه**: سفارش‌ها، دستگاه‌ها، تیکت‌ها و ارزش مشتری کنار تاریخچه ارتباط.
- **نقشه عملیات** با سه لایه: قیف فروش، دستگاه‌های نصب‌شده، خدمات باز.
- هشدار شماره تکراری و هشدار «سرنخ بدون اولین تماس».

**منبع ۲ (Elecio Manager) — زبان بصری:**
پالت تیره (`#253237`، `#E0FBFC`، `#779BE7`، `#FF499E`)، پس‌زمینه شبکه‌ای با محوشدگی شعاعی، کارت‌های شیشه‌ای، منوی کناری جمع‌شونده راست‌چین با گرادیان متحرک برای آیتم فعال، دکمه درخشان صورتی، فونت IRANSansX با ارقام فارسی.

## معماری

```
elecio_flow/
├── shared/            پیش‌فرض‌های فضای کار، نقش‌ها، تقویم شمسی، استان‌ها (مشترک وب و API)
├── server/            Express + SQLite (node:sqlite)
│   └── src/
│       ├── db.ts              اسکیما و توابع کوئری
│       ├── core.ts            احراز هویت، مجوزها، تنظیمات، شماره‌گذاری اسناد
│       ├── services/          منطق دامنه: امتیازدهی CRM، موجودی، موتور جریان کار
│       ├── routes/            API هر ماژول
│       └── seed.ts            پیش‌فرض‌های الکیو + داده نمونه
└── web/               React + Vite + Tailwind + TanStack Query
    └── src/
        ├── components/        کیت رابط کاربری، پوسته، نمودارها، فرم‌ها
        └── pages/             صفحات هر ماژول
```

### آمادگی برای SaaS

- همه جدول‌های کسب‌وکار `org_id` دارند (چندمستأجری).
- **همه مراحل، برچسب‌ها و قواعد داده هستند، نه کد**: مراحل سفارش و تولید (با SLA و کنترل خروج)، مراحل مشتری، منابع سرنخ، انواع مشتری، فیلدهای سفارشی، قواعد امتیاز، چک‌لیست QC، انواع تیکت و SLA، دسته‌های هزینه، پیشوند اسناد و الگوی سریال. هر فضای کار جدید با **پیش‌فرض‌های الکیو** (`shared/defaults.ts`) شروع می‌شود و از صفحه تنظیمات قابل تغییر است؛ دکمه «پیش‌فرض الکیو» هر بخش را برمی‌گرداند.
- لایه دیتابیس پشت چهار تابع (`q`، `one`، `run`، `tx`) است؛ مهاجرت به PostgreSQL فقط همین ماژول را تغییر می‌دهد.

### گام‌های پیشنهادی بعدی

- ثبت‌نام فضای کار جدید (onboarding) و انتخاب قالب پیش‌فرض برای مشتریان SaaS
- اتصال پیامک (پنل‌های SMS.ir / ملی‌پیامک مانند منبع ۱) برای یادآوری پیگیری و اطلاع‌رسانی ارسال
- چاپ رسمی پیش‌فاکتور/فاکتور با سربرگ و برچسب سریال با QR
- ورود گروهی مخاطبین از Excel
- مهاجرت به PostgreSQL و پشتیبان‌گیری خودکار برای استقرار ابری

> فونت IRANSansX از پروژه Elecio Manager کپی شده و تجاری است؛ استفاده از آن تابع مجوز شماست. Vazirmatn (رایگان، OFL) به‌عنوان فونت جایگزین همراه پروژه است؛ برای حذف IRANSansX کافی است فایل‌های آن را از `web/public/fonts` و تعریف‌هایش را از `web/src/index.css` بردارید.
